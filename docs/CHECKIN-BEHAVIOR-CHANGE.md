# 自动签到：默认值判据变更（行为变更说明）

> 关联：`docs/CHECKIN-VERIFY.md` §3 P1-1（"默认关闭不持久"）。
> 变更点：**「已有安装」的判据从「配置文件或签到日志存在」收窄为「仅配置文件存在」。**

## 变更点

`load_checkin_config` 用「使用痕迹」决定 `enabled` 的默认值（读取时派生，不落盘）：

| 场景 | 旧行为 | 新行为 |
| --- | --- | --- |
| 全新安装（无配置文件、无日志） | `enabled: false` | `enabled: false`（不变） |
| **只有签到日志**（从来没打开过自动签到，但手动签过到） | `enabled: true` ⚠️ | **`enabled: false`** |
| 配置文件存在但没有 `enabled` 字段（旧版本写的配置） | `enabled: true` | `enabled: true`（不变） |
| 配置文件损坏但存在 | `enabled: true` | `enabled: true`（不变） |
| 配置文件里有显式 `enabled` | 按配置值 | 按配置值（不变） |

原因：签到日志**不需要开启自动签到就会产生**（单账号「签到」、「全部立即签到」、托盘「一键签到」、账号页「刷新并签到」都会写日志），所以「有日志 = 老用户」会把一次手动签到变成静默开启自动签到——用户没碰过开关，设置页却显示"已开启"。

## 影响人群

**手动签到过、但从未在设置页保存过自动签到配置的老用户。** 这类用户升级后：

- 自动签到会从「隐式开启」回落到「关闭」；
- 设置页开关显示为关闭，且**不会再被签到日志翻回去**。

没手动签到过、或保存过任何一次自动签到配置（哪怕只是拨一下开关再拨回来）的用户**不受影响**。

## 如何重新开启

设置 →「自动签到」→ 打开「启用自动签到」即可；拨动一次就会写入显式配置，之后状态稳定。

## 配套改动（同一批）

- **来源可追溯**：配置读取结果新增派生字段 `enabled_source`（`user` / `legacy_config` / `default`），**只读、不落盘**。设置页在「开关是默认回落而非用户亲手打开」时显示一行提示：「当前为自动启用：检测到历史签到记录或旧版配置，非你手动开启」。
- **`already` 回执补齐**：未设置签到时间段时，后台核验发现"今日已签"也会补写一条 `already` 日志，托盘与账号卡的「今日已签」判定不再整天停在"未签"。
- **「今日已签」口径统一**：当天**任意一条** `success` / `already` 即算已签（此前取"当天最后一条"，一次失败会把判定打回未签）。
- **panic 守护 + 心跳**：周期循环改为在独立任务中执行，任务 panic 只会记录一条失败心跳并继续下一轮，不会再让自动签到静默停摆；设置页展示「上一轮：{相对时间} · {状态}」，超过 2 小时未更新会高亮提示。
